# Synthetic fixtures

Made-up content only: no Klei text, names or numbers. Ids start with `Synth`,
DLC ids are `DLC_ALPHA_ID` / `DLC_BETA_ID`. `manifest.json` lists each file with
the schema it must validate against; `tests/test_fixtures.py` checks all of them.
Use them for tests and mocks. Real game data goes in `fixtures/real/` (gitignored).

## v1.1 additions

- `companion/` mimics the game's `companion/` output folder: `art/` (manifest plus
  placeholder PNGs: solid circles, squares and diamonds, no game art), `theme/<build>/`,
  `commands/`, `acks/`. It is generated by `devtools/make-synthetic-fixtures.py`
  (stdlib; the sha256 and sizes in the manifest are real). Other v1.1 fixtures are plain JSON.
- `art-dupe-d1.png` is the reply fixture of `GET /art/<kind>/<id>`.
- `mod/live-running.json` stays schema 1 on purpose: the core must keep reading it.
  `mod/live-running-v2.json` is schema 2.

## v1.3 additions

Made by `devtools/make-v13-fixtures.py` from made-up data (ids start with `Synth`): the core builds the Screens and
replies itself, so run it again after changing a view. `mod/export-v13.json` and `mod/live-running-v13.json` carry
the overlays, tools, build menu, material candidates, port signal texts, unlock facts and stock;
`screens/actions*.json`, `buildings.json`, `entry-building-*.json` (picker, automation, flow, locked, plain),
`settings-modstate.json`, `api/status-modstate-*.json` (one per mod state), `api/tabs.json`, the pad request bodies,
`api/mod-install-*.json` and `companion/commands|acks/*-14..16.json`. Machine paths are replaced by a made-up folder.
